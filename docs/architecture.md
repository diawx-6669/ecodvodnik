# Архитектура — ЭкоДвойник

## Общая схема

```
[Arduino Uno]                [Ручной ввод]           [Импорт CSV]
 (датчики, Serial)             (веб-форма)             (демо-данные)
       │                          │                        │
       ▼                          │                        │
[serial_bridge.py]                │                        │
 (Serial -> HTTP)                 │                        │
       │                          │                        │
       └──────────────┬───────────┴────────────────────────┘
                       ▼
              POST /api/readings
                       │
                       ▼
           ┌─────────────────────┐
           │   Backend (Express)  │
           │  ─────────────────   │
           │  routes/             │
           │  controllers/        │
           │  services/           │
           │    - analyticsService│  считает потребление, тренды, деньги
           │    - petStateService │  считает настроение/уровень питомца
           │    - aiService       │  генерирует ответы (LLM или rule-based)
           │  models/             │
           │  data/db.json        │  простое файловое хранилище (MVP)
           └─────────┬────────────┘
                      │
                      ▼
           GET /api/analytics/summary
           POST /api/assistant/message
           GET /api/assistant/recommendations
                      │
                      ▼
           ┌─────────────────────┐
           │  Frontend (HTML/JS)  │
           │  ─────────────────   │
           │  index.html           │
           │  js/app.js — логика   │
           │  js/pet.js — питомец  │
           │  css/style.css        │
           └─────────────────────┘
```

## Поток данных

1. **Источник данных**: Arduino Uno печатает реальные показания в Serial-порт,
   `serial_bridge.py` пересылает их на backend по HTTP; либо пользователь
   вводит данные вручную, либо загружается синтетический CSV для демо.
2. **Backend** сохраняет показания, считает аналитику (расход, тренды, деньги,
   аномалии) и определяет состояние питомца.
3. **AI-слой** (`aiService.js`) генерирует персональные рекомендации и реплики
   питомца — либо через реальный LLM (если задан `ANTHROPIC_API_KEY`), либо
   через rule-based логику (работает офлайн, для надёжности демо).
4. **Frontend** отображает дашборд, питомца и чат, обновляется каждые 30 секунд.

## Почему такая архитектура для MVP

- **Простое файловое хранилище** вместо полноценной БД — быстрее поднять
  для хакатона, легко заменить на MongoDB/PostgreSQL позже без изменения
  контроллеров и роутов.
- **Fallback на rule-based AI** — демо никогда не сломается из-за отсутствия
  интернета или ключа API во время презентации.
- **Разделение на модули** (routes/controllers/services/models) — облегчает
  командную работу: разные участники могут работать над разными частями
  параллельно.

## Возможное развитие после хакатона

- Реальная БД + аутентификация пользователей (домохозяйства/школы/бизнес)
- Push-уведомления от питомца (Telegram-бот, мобильное приложение)
- Интеграция с реальными IoT-платформами (MQTT, Home Assistant)
- Сравнение результатов между пользователями (рейтинги, соревнования дворов/классов)
